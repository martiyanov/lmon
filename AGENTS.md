# AGENTS.md — инструкция для ИИ-агентов, работающих с репозиторием lmon

Прочитай CONCEPT.md — это действующие принципы проекта. Кратко:
один статический Go-бинарник, минимум зависимостей (только
`golang.org/x/sys`), лаконичный вывод, честные значения.

## Структура

- `BACKLOG.md` — бэклог задач. Читать в начале сессии. Идеи владельца
  СНАЧАЛА обсуждаются в чате; в бэклог кладём только по явной команде
  («клади в бэклог»). Сам владелец накидывает
  туда задачи, делаем пачками по его команде; закрытое помечать `[x]`
  с номером версии. Новые задачи владельца — сначала туда, не в код.
- `main.go` — CLI, цикл мониторинга, рендер колонок (цифры и блоки),
  заголовок/пороги колонок (`layout()`), градиент цвета.
  Терминал: `term_unix.go` / `term_windows.go` (размер окна; на Windows
  дополнительно включается ANSI-режим консоли через SetConsoleMode).
- `hints.go` — стартовые подсказки: что скрыто/недоступно и что
  установить или указать (`--cpu`, `--gw`, ICMP-правило для Windows).
- `capabilities.go` — какие колонки поддерживает ОС; неподдерживаемые
  скрываются из вывода (Windows: RUN/C°/IOW/SWP/GPU, macOS: IOW/G°).
- `internal/netping/` — пинг через системный `ping` (флаги для
  macOS/Linux разные), парсинг `time=`, ретрай при полной потере.
- `internal/meter/` — метрики системы. Всё платформозависимое —
  файлами с build-тегами (`darwin.go`, `linux.go`, `windows.go`,
  `cpustat_*.go`); парсеры — чистые функции, покрытые юнит-тестами
  в `*_test.go` рядом. `other.go` — заглушки для прочих ОС.
  На Windows часть WinAPI зовётся напрямую через LazyDLL — эти
  функции не обёрнуты в используемой версии x/sys.
- `legacy/lmon.zsh` — исходная zsh-версия, заморожена, не трогать.
- `scripts/update-tap.sh` — обновление формулы homebrew-tap.
- `scripts/release-local.sh` — локальный релиз: CI в Colima,
  сборка в чистом клоне на теге, `gh release create`, тап.

## Команды

```sh
go vet ./... && go test ./...     # проверка
go build -o lmon .                # сборка
./lmon --cpu --swap -b 5          # быстрая проверка руками
./scripts/test-all.sh             # полная локальная матрица (см. ниже)
./scripts/release-local.sh v1.2.3 --notes-file /tmp/notes.md  # релиз
```

## Тесты и релизы

GitHub Actions включён (ubuntu-only), но очередь у него периодически
залипает: job может висеть в `queued` час и больше. Поэтому основной
путь — локальная матрица, а релиз публикуется локально через `gh`.

CI: `scripts/test-all.sh` — gofmt/vet/test/-race на маке, vet+test в
`golang:1.22-alpine` через colima (реальный Linux), проверка сайта docs
и кросс-сборка всех шести платформ. Нужен `colima start`.
Единственное, что не покрыто, — запуск тестов на настоящей Windows
(кросс-сборка остаётся; идея с KVM/QEMU — в BACKLOG.md).

Релиз:
1. `scripts/test-all.sh` — зелёное.
2. Поднять `const version` в `main.go`, коммит, пуш в `main`.
3. Аннотированный тег `vX.Y.Z`, пуш тега. **Теги не перематывать**:
   sum.golang.org запоминает хэш версии — правка только новым номером.
4. `scripts/release-local.sh vX.Y.Z --notes-file notes.md` — прогоняет
   CI, собирает goreleaser в чистом клоне на теге, публикует Release и
   ассеты через `gh`, обновляет Homebrew-тап. Флаги: `--skip-ci`
   (быстрый повтор), `--update` (перезалить ассеты существующего
   релиза), `--no-tap`, `--dry-run`.
5. `brew upgrade lmon` локально; проверить `lmon --version`.

Требования к локальному релизу: `gh auth login` (scope repo),
`goreleaser`, `docker`/`colima`, `git` с доступом к origin по SSH.

## Железные правила

- Новые колонки — только через флаги; базовый набор N G L M T не менять.
  Колонки, которых в ОС нет, скрываются автоматически (capabilities.go) —
  это не изменение базового набора, а честный вывод.
- Платформозависимый код — в `internal/meter` с build-тегами и тестом
  парсера на реальном образце вывода.
- Windows-особенности: вывод ping.exe локализован — regex в netping
  понимает `time=` и `время=`; load average и температура недоступны —
  колонки L/T скрываются (как IOW/SWP/GPU), стартовые подсказки говорят
  об этом и предлагают `--cpu`; не менять на «примерные» значения.
- Значение «нет данных» — `-1` внутри, `·` на экране; unreachable — 999.
- Зависимости: добавление новой библиотеки требует серьёзного
  обоснования — сначала попробуй sysctl/procfs/sysfs/exec системной
  утилиты.
- Вывод вhelp и README синхронизируй при изменении колонок/порогов.
