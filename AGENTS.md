# AGENTS.md — инструкция для ИИ-агентов, работающих с репозиторием lmon

Прочитай CONCEPT.md — это действующие принципы проекта. Кратко:
один статический Go-бинарник, минимум зависимостей (только
`golang.org/x/sys`), лаконичный вывод, честные значения.

## Структура

- `main.go` — CLI, цикл мониторинга, рендер колонок (цифры и блоки),
  заголовок/пороги колонок (`layout()`), градиент цвета.
- `internal/netping/` — пинг через системный `ping` (флаги для
  macOS/Linux разные), парсинг `time=`, ретрай при полной потере.
- `internal/meter/` — метрики системы. Всё платформозависимое —
  файлами с build-тегами (`darwin.go`, `linux.go`, `cpustat_*.go`);
  парсеры — чистые функции, покрытые юнит-тестами в `*_test.go`
  рядом. `other.go` — заглушки для прочих ОС.
- `legacy/lmon.zsh` — исходная zsh-версия, заморожена, не трогать.
- `scripts/update-tap.sh` — обновление формулы homebrew-tap.

## Команды

```sh
go vet ./... && go test ./...     # проверка
go build -o lmon .                # сборка
./lmon --cpu --swap -b 5          # быстрая проверка руками
docker run --rm -v "$PWD":/src -w /src golang:1.22-alpine go test ./...
                                  # прогон Linux-тестов с макa
```

`go.mod` держит `go 1.22` — не поднимай без причины (совместимость).
CGO всегда выключен (`CGO_ENABLED=0` в goreleaser).

## Релиз

1. Поднять `const version` в `main.go`, коммит, пуш в `main`.
2. Тег `vX.Y.Z` и пуш тега — Release-воркфлоу (goreleaser) соберёт
   тарболлы/.deb/.rpm/checksums в GitHub Release автоматически.
3. Дождаться зелёного воркфлоу, затем `scripts/update-tap.sh vX.Y.Z`
   (обновит формулу в `~/Проекты/homebrew-tap` через SSH).
4. **Теги никогда не перематывать**: sum.golang.org навсегда
   запоминает хэш версии — правка = только новый номер версии.

## Инварианты

- Новые колонки — только через флаги; базовый набор N G L M T не менять.
- Платформозависимый код — в `internal/meter` с build-тегами и тестом
  парсера на реальном образце вывода.
- Значение «нет данных» — `-1` внутри, `·` на экране; unreachable — 999.
- Зависимости: добавление новой библиотеки требует серьёзного
  обоснования — сначала попробуй sysctl/procfs/sysfs/exec системной
  утилиты.
- Вывод вhelp и README синхронизируй при изменении колонок/порогов.
